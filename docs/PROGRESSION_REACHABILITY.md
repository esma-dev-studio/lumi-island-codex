# 図鑑・解放の到達可能性

検証日: 2026-08-03
図鑑総数: 18種

## 節目

百分率表示の丸めではなく、必要数を切り上げて判定する。

| 節目 | 必要数 | 実際に増える遊び |
|---|---:|---|
| 25% | 5 | 8ルーメンと次の発見案内 |
| 50% | 9 | 港の釣りデッキ、港専用魚2種、12ルーメン |
| 75% | 14 | 夜の庭、夜限定植物2種、18ルーメン |
| 100% | 18 | 図鑑完成表示と次の島づくり案内 |

## 通常プレイの到達経路

```text
開始
 ├─ 池の魚 3種（同じ池で有限回）
 ├─ 基本の採集 10種（同じ種類の採集場所でも未発見を優先）
 └─ 橋を購入して小島限定素材 1種
        ↓
     14 / 18（75%到達、夜の庭が開く）
        ├─ 50%で開いた港の専用魚 2種
        └─ 夜の庭の夜限定植物 2種
              ↓
           18 / 18（100%）
```

実際の空セーブE2Eでは、基本採集10種→港魚2種→小島素材1種→池魚1種で14/18へ到達し、夜の庭2種→池の残り2種で18/18へ到達する。

## アイテム別の前提

| 区分 | 数 | 前提 | 前提自身のアイテムを要求するか |
|---|---:|---|---|
| 開始時から取得可能 | 13 | 時間帯または通常エリア | いいえ |
| 小島限定 | 1 | ルーメンで橋を修理 | いいえ。橋は図鑑率と独立 |
| 港専用魚 | 2 | 図鑑9/18 | いいえ。9種は港なしで取得可能 |
| 夜の庭 | 2 | 図鑑14/18 | いいえ。14種は夜の庭なしで取得可能 |

夜の庭を除いて14種あるため、夜の庭の2種を75%到達条件に使う循環はない。最終到達可能数は18、未到達IDは0件。

## 魚の有限到達性

魚抽選は次の共通コンテキストを使う。

```ts
type FishingContext = {
  fishingSpotId: string;
  gameDay: number;
  timeOfDay: TimeWindow;
  catchCountAtSpot: number;
  discoveredFishIds: string[];
};
```

候補はhabitatと`activeTimes`で絞り、`baseWeight`とrarityで重み付けする。未発見魚には発見補正を掛ける。場所・日・時間・回数・発見済みIDからシードを作るため、テストは再現可能で、通常プレイでは毎回同じ魚へ固定されない。

発見可能な魚が未発見で残る序盤は未発見候補を有限回で選ぶルールを持つ。自動検証では、同一池から6回以内に池3種、同一港から4回以内に港2種を取得し、同じコンテキスト列を再実行して同じ結果になる。

図鑑の時間帯ヒントはFishDefinition.activeTimesから生成し、出現判定との二重管理をしない。島ランク2で朝と夕方、島ランク3で夜を選べるため、子どもが待ち続けなくても全時間帯を正規操作で作れる。

## 自動失敗条件

`analyzeProgressionReachability()` とRelease Candidateテストは次を失敗条件とする。

- 25 / 50 / 75 / 100%のいずれかへ到達不能
- 夜の庭を開く前の取得可能数が14未満
- 解放後も取得不能なIDが1件以上
- 夜の庭の取得物が75%到達に必要
- 同じ釣り場の有限回シミュレーションで全魚が出ない
- 選択順を変えた経済シミュレーションが2回目の購入前に停止する

## セーブ整合性

- 釣り回数は`fishingCatchCounts[sourceId]`へ保存する
- 初発見日は`collectionFirstSeenDay[id]`へ保存する
- 購入済みヒントは`unlockedCollectionHintIds`へIDで保存する
- 旧version 1〜4はversion 5へ移行し、欠損フィールドを空の安全値で補う
