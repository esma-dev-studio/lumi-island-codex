# Lumi Island Release Candidate 最終レポート

作成日: 2026-08-03
対象: Phase 2.3（総合68点）からのリリース候補改善

## 総合判定

**81 / 100点 — 条件付きリリース候補**

進行不能、同じ釣り場で同じ魚しか出ない問題、解放と遊びの未接続、情報量過多、購入判断の弱さを解消した。空セーブから18/18まで到達し、保存・再読込できる実操作E2Eも追加した。一方で、キャラクターGLBは本番用アセットではなく、低性能の物理端末でも未検証である。この2点は商品品質へ向けた次の課題として残す。

## 1. 監査で見つかった主な問題

- 魚IDが釣り場IDでほぼ固定され、図鑑75%へ安定して到達できなかった。
- 夜の庭の解放条件と夜限定収集物が循環依存する可能性があった。
- 港、橋、森、島ランクが「表示・フラグ」中心で、新しい遊びへの接続が弱かった。
- 初期報酬と価格差が小さく、買い物の選択に意味が出にくかった。
- HUD、目的、メニューが重複し、小学2年生が次にすることを迷いやすかった。
- キャラクターと環境のGLBは仮素材で、3D品質の目標には未到達だった。

## 2. 図鑑75%で止まる根本原因

釣果を `sourceId` だけで決めていたため、同じ池や港を繰り返しても新種が増えなかった。さらに解放前に集められる種類数と、夜の庭の必要数が設計上明示されていなかった。場所・日・時間帯・その場所での釣果回数・発見済み魚IDを入力にした決定的な重み付き選択へ変更し、未発見種を優先した。

## 3. 釣りと時間条件の修正

- 池は3種、港は2種を有限回のプレイで取得できる。
- 釣り開始時に魚候補と時間帯を固定し、ミニゲーム中の時刻変化で魚が別種へ変わらない。
- 朝まで眠る／夕方まで休む／夜まで待つ島ランク行動を実時間へ接続した。時間を戻す場合は翌日へ進む。
- 釣果回数を場所別に保存し、再読込後も選択ロジックが継続する。

## 4. 図鑑25 / 50 / 75 / 100%の到達ルート

| 到達点 | 必要数 | 代表ルート | 次に開くもの |
|---|---:|---|---|
| 25% | 5 / 18 | 最初の採集・工作・会話 | 島づくりの入口 |
| 50% | 9 / 18 | 通常エリアの採集と釣り | 港・森・橋への判断材料 |
| 75% | 14 / 18 | 港2魚、橋先素材、池の魚 | 夜の庭 |
| 100% | 18 / 18 | 夜植物2種と残りの池魚 | 完成記録と継続目標 |

厳密な取得可能数と依存関係は `docs/PROGRESSION_REACHABILITY.md` に記録した。

## 5. 解放後に実際に増える遊び

- 森: 新しい採集対象と3段階の発展、専用依頼。
- 港: 港専用魚2種。
- 橋: 通行可能化と、渡った先の星しずく草。
- 夜の庭: 夜だけ取れる植物2種。
- 島ランク: 朝・夕方・夜を選び、時間条件を子ども自身が作れる。

## 6. 最初の30〜45分の体験

初期8Lから始まり、チュートリアル完了と最初の依頼で20Lを獲得する。18Lの森を最初に選ぶか、10Lの図鑑ヒントを買って次の発見を優先するかを選べる。その後、24Lのレシピ、32Lの橋、森の次段階へ進む。短時間で1回目、続けて2回目の購入が発生する価格帯に調整した。

## 7. 経済バランス

収集家、釣り中心、島づくり中心、依頼中心、寄り道型の5スタイルを80分相当でシミュレーションした。全スタイルで進行停止なし、30分までに初回・2回目の購入が成立した。価格と根拠は `docs/ECONOMY_BALANCE.md` に記録した。

## 8. 小学2年生向けUX

- 常に表示する主目的を1件へ統合。
- トップメニューを4項目へ整理。
- 島づくりを「今できる／もうすこし／できた」の3タブへ分離。
- 漢字には読みを添え、短い動詞から行動を選べるようにした。
- 主要ボタンは文字とCSSアイコンを組み合わせ、絵文字依存を減らした。
- タブレット横画面向けにHUD、メニュー、タッチ領域を調整した。

## 9. 3D表現とカメラ

橋、森、港、夜の庭は見た目だけでなく衝突・採集・時間条件へ接続した。描画品質を low / standard / high に分け、端末条件に応じて解像度、影、粒子、Glowを変更する。カメラと入力の既存挙動は維持し、タッチ入力の離脱・キャンセルもE2Eで確認した。

## 10. GLBとCharacter Gate

GLBは4ファイル、合計1,100,168 bytes。本番用の著作権確認済みキャラクターが未提供であるため、Character Gateは **failed** のままとした。仮素材を高品質完成品として扱わず、3D表現の得点を7/15に抑えている。

## 11. パフォーマンス

- ビルド済みJavaScript合計: 3,465,947 bytes
- 最大クライアントチャンク: 1,026,065 bytes
- `GameCanvas` 初期静的依存: 1,868,205 bytes / 36 files
- 動的依存: 2,736,685 bytes / 130 files
- 低品質プロファイルは高品質より解像度・影・粒子・Glowの全主要設定を抑える。

数値は `artifacts/release-candidate-metrics.json` から取得した。実ブラウザでは1280×720と1024×640を確認し、ページの横あふれは0、ホームの縦あふれも0、console error / warningは0件だった。図鑑は18枠を扱うためパネル内部だけをスクロールさせる。実機の低性能タブレットでのFPS・メモリ検証は未実施であり、SwiftShaderによるソフトウェア描画E2Eを代替証跡とする。

## 12. 空セーブ完全E2E

新規ゲームから、歩行、採集、工作、家具配置、NPC会話、森購入、港2魚、橋修理、島への移動、夜の庭、池3魚、18/18、手動保存、再読込までを実操作するシナリオを追加した。図鑑数やルーメンを途中注入せず、実際に得た状態だけで完走する。

## 13. 進行到達性

25 / 50 / 75 / 100%の各しきい値は5 / 9 / 14 / 18。夜の庭を開く前に14種取得可能で、循環依存はない。各解放が少なくとも1つの操作または収集物を追加することを単体テストで固定した。

## 17. 分割・整理した責務

魚の定義・候補生成・選択、進行到達性・解放効果・次目的、経済設定・シミュレーション、環境描画品質を独立モジュールへ分けた。巨大な `IslandScene.ts` は依然として残るため、次フェーズではエリア生成、衝突、エフェクト、相互作用の4系統へ段階分割する。

## 18. セーブ移行

セーブversionを5へ更新した。version 1〜4からの読込時は、釣り場別回数、初発見日、購入済みヒントID、森依頼完了を安全な初期値で補う。version 5の保存・復元と旧版sanitizeを単体テストで確認した。

## 19. 未解決事項

1. 本番用キャラクターGLBとアニメーションの差し替え。
2. 低性能の物理タブレット／学校PCでのFPS、メモリ、発熱、長時間安定性の計測。
3. 最大1MBのCharacterViewチャンクの追加分割。
4. `IslandScene.ts` の責務分割。
5. 18/18後の週単位イベント、複数セーブ、保護者向け時間管理は次フェーズ。
